## 6. Acceptance checks

Go-live needs every box ticked. Each check is done on the client's desk with practice data.

- [ ] A website-form request becomes one card on the Queue, with the customer's words saved exactly.
- [ ] Sending the same request twice adds to the first card. It does not make a second card.
- [ ] A typed-in request becomes one card.
- [ ] AIA's work package appears beside the request, with Accept / Fix / Reject on each item.
- [ ] Accepting an item does not send anything.
- [ ] A request that asks "when?" and "how much?" shows separate **Needs a person** items. The draft promises no time and no price.
- [ ] A Responder cannot press Yes. An Approver can.
- [ ] Editing a reply after Yes cancels the Yes.
- [ ] An approved reply goes out once, and only through the channel named in section 2. Pressing again does not send it twice.
- [ ] If a send fails, the card shows **Try again** and **I sent it myself**. A manual send is recorded as "Sent by a person (manual)".
- [ ] A customer reply lands on the same card.
- [ ] **Kill** needs a reason and a second tap.
- [ ] Another business's desk cannot see this desk's cards.
- [ ] The live channel named in section 2 passes its own test. [PLACEHOLDER: channel test steps once the channel is chosen.]
- [ ] Staff complete a practice card using only the staff guide.
